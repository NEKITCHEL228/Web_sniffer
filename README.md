## Введение

**Цель:** Создание кроссплатформенного ПО для анализа сетевого трафика и отправляемых/получаемых пакетов.

### Возможности системы

- Захват сетевых пакетов (при помощи библиотеки libpcap)
- Анализ сетевого трафика
- Отображение информации о пакетах
- Сбор статистики на основе трафика

### Области применения

- Анализ сети
- Обучение
- Диагностика сетевых проблем

---

## Термины и аббревиатуры

| Термин | Определение |
|--------|------------|
| **Sniffer (Сниффер)** | Программа для перехвата и анализа сетевого трафика |
| **Packet (Пакет)** | Единица передачи данных в сети |
| **libpcap** | Библиотека на C++ для захвата пакетов |
| **Сетевой протокол** | Набор строгих правил, стандартов и форматов, определяющих обмен данными в сети |
| **IP** | Internet Protocol — интернет протокол |
| **TCP** | Transmission Control Protocol — протокол, гарантирующий доставку пакетов |
| **UDP** | User Datagram Protocol — быстрый протокол, не гарантирующий доставку пакетов |
| **ICMP** | Internet Control Message Protocol — протокол для обмена диагностическими сообщениями |
| **Интерфейс** | Совокупность методов, средств и правил, обеспечивающих взаимодействие между двумя системами |
| **Promiscuous mode** | Режим захвата всех пакетов интерфейса |

## Общее описание

### Описание продукта

Система представляет кроссплатформенное GUI-приложение, работающее на компьютере пользователя. Оно взаимодействует с сетевым интерфейсом ОС и библиотекой libpcap для анализа сетевых пакетов.

### Функции продукта

- Захват сетевых пакетов
- Анализ структуры пакетов
- Отображение данных
- Подсчёт статистики
- Фильтрация трафика
- Сохранение данных

### Характеристики пользователей

Пользователь имеет базовые / продвинутые знания сетей и использует систему для обучения / диагностики.

## Требования

### Бизнес-требования

- Разработать инструмент для мониторинга и анализа сетевого трафика
- Повысить эффективность диагностики сетевых проблем
- Обеспечить выявление аномалий и угроз безопасности в сети
- Снизить время поиска неисправностей в сети
- Предоставить удобный инструмент для обучения сетевым технологиям

### Пользовательские требования

- Захват сетевых пакетов в реальном времени
- Просмотр информации об IP-адресах отправителя и получателя
- Определение используемых протоколов (TCP, UDP, ICMP)
- Извлечение статистики по трафику (объём, количество пакетов)
- Фильтрация трафика
- Сохранение результатов анализа в файл

### Функциональные требования

- Используется библиотека libpcap для перехвата пакетов
- Сетевой интерфейс переводится в Promiscuous mode
- Пакеты захватываются в реальном времени
- Система извлекает:
  - IP-адрес источника и назначения
  - тип протокола
  - размер пакета
- Декодирование заголовков сетевых протоколов
- Система подсчитывает:
  - общее количество пакетов
  - объём переданных данных
  - распределение по протоколам
- Обновление статистики в реальном времени
- Фильтрация пакетов:
  - по IP-адресу
  - по порту
  - по протоколу
- Сохранение захваченных пакетов в файл (формат pcap)
- Чтение ранее сохранённых данных
- Читаемый формат представления пакетов

### Нефункциональные требования

- Язык разработки: **C++**
- Обработка не менее **1000 пакетов/сек**
- Задержка обработки пакета не должна превышать **10 мс**
- Пакеты не теряются при нормальной нагрузке
- Ошибки сети обрабатываются корректно
- Система не должна изменять сетевой трафик (пассивный анализ)
- Интерфейс представлен в виде GUI
- Вывод структурированный
- Кроссплатформенность

## Архитектура и паттерны проектирования

### Порождающие паттерны

#### Одиночка (Singleton)

Реализован для классов управления глобальными ресурсами:

- **Statistics** — накопление суммарных количественных и объемных метрик трафика, распределение протоколов, обнаружение шифрованных сессий.
- **AnomalyDetector** — централизованный узел поведенческого анализа, счётчики потенциальных угроз (SYN-Flood, сканирование подозрительных портов), идентификация хостов-акторов.
- **FileManager** — изолирует операции чтения-записи бинарных дампов пакетов, гарантируя бесконфликтную сериализацию pcap на диск.

Конструкторы классов скрыты в секции `private`; доступ к экземплярам через статические методы `getInstance()`.

#### Фабричный метод (Factory Method)

Реализован в виде статического класса `PacketFactory::createPacket(rawData, length)`. Фабрика разбирает заголовки Ethernet, IP и транспортных слоёв и возвращает `std::shared_ptr<Packet>` на конкретный наследник — `TcpPacket`, `UdpPacket` или `IcmpPacket`.

### Структурные паттерны

#### Адаптер (Adapter)

Класс `Sniffer` выступает объектно-ориентированным адаптером для низкоуровневого C-интерфейса libpcap (Npcap): запускает внутренний поток захвата, скрывает вызов `pcap_loop()`, очищает структуры данных и трансформирует байтовые блоки pcap в типизированные C++ структуры.

#### Фасад (Facade)

Класс `SnifferFacade` минимизирует связность между GUI и логическим ядром. UI вызывает только методы фасада (`startCapture()`, `stopCapture()`, `applyFilter()`), а фасад самостоятельно управляет всеми подсистемами.

### Поведенческие паттерны

#### Наблюдатель (Observer / Publisher-Subscriber)

Реализован на базе Qt Signals & Slots. Класс `Sniffer` генерирует сигнал `packetCaptured(std::shared_ptr<Packet>)`, `SnifferFacade` транслирует информацию в детекторы аномалий/статистики и отправляет сигнал `packetProcessed()` для обновления графической сцены.

#### Интерпретатор (Interpreter)

Система фильтрации строит абстрактное синтаксическое дерево (AST) из пользовательских выражений вида:

```
(ip.src == 192.168.1.1 and tcp.port == 443) or ip.proto == UDP
```

Узлы дерева:
- **ConditionNode** — сравнение конкретного поля пакета со значением
- **LogicalNode** — логические операции AND / OR между поддеревьями
- **NotNode** — унарное отрицание узла

`FilterParser::parse(query)` трансформирует текстовый запрос в дерево AST, вычисляемое для каждого пакета.

## Тестирование

### Сценарий 1 — Генерация, фильтрация и сохранение пакетов в файл PCAP

**Файл:** `tests/scenarios/scenario_1.cpp`

Эмулирует этап захвата и первичного экспорта трафика. Генерирует тестовый набор пакетов (TCP, UDP, ICMP), применяет AST-фильтр `tcp.port == 80`, сериализует результат через `FileManager` в PCAP-файл. Валидирует работу парсера AST, фабрики и подсистемы сохранения.

### Сценарий 2 — Загрузка пакетов из файла PCAP и сбор статистики

**Файл:** `tests/scenarios/scenario_2.cpp`

Верифицирует чтение и аналитику исторических дампов трафика. Парсит pcap-файл из Сценария 1, восстанавливает объекты через `PacketFactory`, передаёт пакеты в `Statistics` для подсчёта суммарных байтовых объёмов и распределения по протоколам.

### Сценарий 3 — Инициализация сниффера и поиск доступных интерфейсов

**Файл:** `tests/scenarios/scenario_3.cpp`

Тестирует взаимодействие с драйверами Npcap/libpcap. Вызывает `Sniffer::getAvailableInterfaces()`, проверяет получение системных дескрипторов имён устройств и их дружественных описаний.

### Сценарий 4 — Оценка сложных логических фильтров

**Файл:** `tests/scenarios/scenario_4.cpp`

Верифицирует грамматический разбор комбинированных условий. Компилирует выражение `(ip.src == 192.168.1.1 and tcp.port == 443) or ip.proto == UDP` в AST и прогоняет через него тестовый пакетный массив. Подтверждает детерминированное и корректное вычисление вложенных логических ветвей.

### Сценарий 5 — Обнаружение сетевых аномалий и оценка угроз

**Файл:** `tests/scenarios/scenario_5.cpp`

Верифицирует модуль `AnomalyDetector`. Подаёт аномальные пакеты (закрытые подозрительные порты, признаки DoS/SYN-Flood). Проверяет своевременность обработки инцидентов, обновление индикаторов атак и генерацию системных оповещений.

## Контейнеризация (Docker)

**Сборка образа:**
```bash
docker build -t web-sniffer-prime .
```

**Запуск тестов:**
```bash
docker build --target builder -t web-sniffer-tester . && \
docker run --rm -it web-sniffer-tester sh -c \
  "cd /app/build && export QT_QPA_PLATFORM=offscreen && ctest -V"
```

**Запуск программы (GUI):**
```bash
docker run --rm -it \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  -e DISPLAY=host.docker.internal:0.0 \
  web-sniffer-prime
```
